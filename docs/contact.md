# Contact Page Product Requirements Document (PRD)
Version: 1.0

> This document defines the contact and consultation experience for the public website.

---

# Purpose

The Contact page gives visitors a simple way to reach the right person, request a consultation, ask a question, or find company information.

The page must route inquiries accurately without presenting an overwhelming form.

---

# Primary Goals

- Capture qualified inquiries
- Route leads correctly
- Reduce response time
- Set clear expectations
- Support phone, email, form, and appointment scheduling

---

# Inquiry Types

- Buying
- Selling
- Property Wealth Management™
- Renting
- Investing
- Concierge
- Homeowner Support
- Vendor Inquiry
- Media or Built in the 757™
- General Question

---

# Page Structure

1. Hero
2. Contact Options
3. Smart Inquiry Form
4. Appointment Scheduling
5. Office Information
6. Service Area
7. Response Expectations
8. FAQ
9. Footer

# Smart Form Fields

Required:

- First Name
- Last Name
- Email
- Phone
- Inquiry Type
- Preferred Contact Method
- Message
- Consent

Conditional:

- Property Address
- Buying Timeline
- Selling Timeline
- Rental Address
- Investment Goals
- Number of Properties
- Appointment Preference
- File Upload

---

# Routing Rules

Buying:
Buyer pipeline

Selling:
Seller pipeline

Property Wealth Management:
Owner lead pipeline

Renting:
Rental inquiry pipeline

Investing:
Investor pipeline

Concierge:
Concierge pipeline

Media:
Built in the 757™ pipeline

General:
Administrative review queue

---

# Automation

On submission:

1. Validate form
2. Create or update contact
3. Create inquiry record
4. Apply audience and intent tags
5. Route to correct pipeline
6. Assign owner
7. Send confirmation
8. Create response task
9. Notify team
10. Log source and campaign

---

# Scheduling

Support:

- Consultation type
- Available time slots
- Time-zone handling
- Confirmation email
- Reminder notifications
- Rescheduling
- Cancellation
- Calendar integration

---

# Spam and Security

- CAPTCHA or bot protection
- Rate limiting
- Input validation
- File scanning
- Consent logging
- No sensitive financial data in free-text forms

---

# Analytics

Track:

- Form starts
- Form completion
- Abandonment
- Inquiry type
- Appointment bookings
- Source campaign
- Response time
- Lead conversion

---

# Accessibility

- WCAG AA
- Proper labels
- Error summaries
- Keyboard navigation
- Accessible date and time controls
- Clear required-field indicators

---

# Acceptance Criteria

- Every inquiry routes correctly
- Duplicate contacts are handled safely
- Confirmation messages are sent
- Calendar bookings sync correctly
- Consent is recorded
- Spam protection is active
- Analytics capture the complete conversion funnel
